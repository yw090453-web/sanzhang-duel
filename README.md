# 三张·对决

“静夜牌桌”风格的三张牌游戏，支持手机/电脑浏览器。包含 2–8 人好友联机，以及原有的 1 名真人对战 3 名电脑的 8 局单机模式。

- 积分只用于游戏内计分，不涉及真实金钱，没有任何购买、转让或兑换渠道。
- 联机：Koa + Socket.IO 后端，免注册昵称、6 位房间码、邀请链接、准备开局、断线恢复；只记录房间积分。
- 单机：无需后端，本地存档和战绩仍保存在 localStorage。
- 原仓库完整快照见 `vendor/README.md`；可运行的适配后端在 `server/`。

## 运行

建议 Node.js 22 LTS。

```bash
npm install
npm run build      # 类型检查 + 生产构建，输出到 dist/
npm start          # 前端 + 联机后端，http://localhost:3001
npm test           # 运行全部自动化测试（Vitest）
npm run typecheck  # 仅做 TypeScript 类型检查
```

**手机游玩：**手机与电脑连接同一 Wi-Fi，电脑保持 `npm start` 运行，在手机浏览器打开 `http://电脑的局域网IP:3001`。例如电脑 IP 为 `192.168.1.26`，则打开 `http://192.168.1.26:3001`。每位玩家使用自己的浏览器身份，创建/输入房间码，至少两人准备后自动开局。电脑防火墙需允许该端口在所需网络上访问；访客 Wi-Fi 的客户端隔离可能阻止设备互访。

开发时开两个终端，分别运行 `npm run server:watch` 和 `npm run dev`；Vite 会代理 `/api` 和 `/socket.io` 到 3001。`npm run preview` 只预览静态构建，不提供联机后端。

**公网部署：**见 `DEPLOYMENT.md`。GitHub 可保存源码，GitHub Pages 只能托管静态页面，无法运行联机服务。完整联机版请部署到支持常驻 Node.js 或 Docker、WebSocket 的服务器。

## 联机玩法与边界

- 创建 4/6/8 人上限的房间；2 人即可玩，所有在座玩家准备后自动开始。
- 每局底分 1，暗牌投入 1–5 分，明牌翻倍至 2–10 分。每次加码提升一个档位；首轮不可比牌，后续比牌费用等于跟进费用。
- 成绩从 0 开始，允许负分；每局净得分总和为 0。积分没有购买、兑换、转账或提现渠道，也不设管理加分接口。
- 每步 45 秒，超时自动弃牌；最多 20 轮后自动摊牌。牌力相同则比牌发起方输，强制摊牌相同则平分积分池。
- 服务器独立洗牌、保管暗牌、核对玩家身份、回合号和费用。浏览器只能收到自己已查看的手牌，结算后公开全部牌。
- 刷新或掉线在 2 分钟内可恢复座位；当前行动计时不会因刷新暂停。同一浏览器身份在两个窗口打开时，后者接管前者。
- 主动离桌视为本局退出，房主离开会自动移交。所有人离桌后房间删除。
- 当前为单进程、内存房间：服务重启清空房间和成绩，空闲 30 分钟清理。没有永久账号、数据库、跨服务器扩展或好友聊天。

## 单机规则摘要（与实现一致）

- **开局**：每局四人恢复 1000 积分并自动投入 10 分底分（余额 990，公共积分 40），基础档位 10。
- **座次**：第一局起始座位随机，之后每局顺时针移动一位；每轮从起始座位开始顺时针遍历，跳过已退出者。每局最多 6 轮。
- **看牌**：不扣分、不结束回合、不可撤销；其他人只知道“已看牌”。
- **跟进**：未看牌 = 档位，已看牌 = 档位 × 2；不追补之前的差额。
- **加码**：档位 10→20→40 逐级提高，按新档位与自身看牌状态扣费，不再另扣跟进费；已行动者不会在本轮重新行动；40 档后禁止加码。
- **比牌**：第 2 轮起、发起者必须已看牌、目标必须是仍在局内的其他人；费用为跟进费用 × 2（40/80/160），替代跟进；被挑战者不付费、不能拒绝；牌力小者出局，完全相同则发起者出局；只公布谁与谁比、谁获胜，不展示牌面；未看牌的被挑战者获胜后仍未看牌。
- **弃牌**：立即退出，投入不返还。
- **结束**：只剩 1 人时立即结束并获得全部公共积分；第 6 轮结束仍有多人则自动摊牌，仅在留场者中比较。摊牌并列时平分，余数从起始座位顺时针只给并列获胜者逐人 1 分。
- **牌型**：豹子 > 同花顺 > 同花 > 顺子 > 对子 > 单张。A-K-Q 最大顺、A-2-3 最小顺（小于 2-3-4），K-A-2 不算顺子；不比花色；不启用“235 吃豹子”。通用比较函数在完全相同时返回相等，“比牌时发起者落败”只在比牌动作中处理。
- **成绩**：本局净得分 = 结算后积分 − 1000；本场成绩为各局净得分之和；同分并列排名，不以获胜局数区分。

## 工程要点

- **引擎校验**：所有动作经 `applyAction` 校验，非法调用返回错误且不修改状态；按钮禁用只是界面提示。
- **防重复**：每次结束回合的动作使 `turnId` 递增，真人与电脑提交都携带当前 `turnId`，过期提交被拒绝；电脑定时器按状态版本登记，版本不符即作废，且同一状态只会有一个定时器。
- **信息隔离**：电脑策略只接收 `buildObservation()` 生成的深拷贝，未看牌时 `hand` 为 `null`，不含任何他人暗牌。测试验证：公开信息与随机输入相同时，改变其无权查看的手牌不会改变决策。
- **不变量**：`checkInvariants()` 检查积分守恒（余额和 + 公共积分 = 4000）、非负积分、结算只发生一次、净得分和为 0。测试在每一步状态转换后调用它。
- **存档**：每次有效动作后保存整场状态（含已发的牌），刷新后原样恢复，不重新发牌、不重复扣底分或结算。读取时做结构与不变量校验，损坏时明确提示并允许删除重开，不会计入战绩。整场结束时写入一条战绩（按对战编号去重）。
- **动画与规则分离**：状态更新由控制器完成，动画（翻牌、档位切换、行动提示）只根据状态渲染；操作后短暂锁定真人按钮。

## 自行决定的非核心细节

- 座位：真人固定在底部（座位 0），顺时针依次为左（青岚·谨慎型）、上（石衡·均衡型）、右（赤焰·主动型）。
- 刷新页面时若有未完成对局，直接回到对局页；从暂停菜单“返回首页”则保留存档，首页显示“继续对局”。
- 开始新对战会放弃未完成的存档（有确认弹窗），未完成的对战不计入战绩。
- 电脑行动速度可选 慢/标准/快（约 1.5s / 0.95s / 0.45s 一步），电脑看牌后给出结束动作的间隔为该值的 60%。
- 真人退出本局后默认“观看剩余对局”，可切换“快进至结算”（每步约 60ms）；快进只缩短等待，下一局自动恢复正常速度。
- 本局结束后在牌桌上停留约 1.8 秒（此时翻开所有手牌）再进入结算页；本局结束后不能再暂停。
- 获胜局数（仅展示用）中，并列获胜也计为获胜一局。
- 理论上单局最大投入为 10 + 6 × 160 = 970 < 1000，因此不会出现积分不足；引擎仍保留“积分不足”校验作为保护。
- 存档中保存全部手牌（刷新恢复所必需）。本地单机版只在程序结构上做信息隔离，**不具备任何防作弊能力**。
- 真人面朝下的牌不渲染牌面到 DOM，但如上所述，存档与内存中仍有完整数据。

## 已知限制

- 单机与联机是独立模式，不共享战绩；联机目前没有永久账号、自动匹配或聊天。
- 电脑策略是启发式，不追求最优，也不会根据你的成绩调整；发牌完全随机，没有任何控牌或补偿机制。
- 未做国际化，界面仅中文。
- 在 Claude 桌面应用的“Windows 打包目录”中运行开发服务器时，Vite 解析的 realpath 会指向无法读取的重定向路径，因此 `vite.config.ts` 设置了 `resolve.preserveSymlinks: true`；在普通目录中这一设置没有副作用。
